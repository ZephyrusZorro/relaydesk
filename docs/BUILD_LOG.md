# Build ledger

- Scope: an original IT support project, primarily n8n, Docker and a browser/voice portal with optional email intake.
- Authorization: choose and deliver in one prompt; no additional design approval gate is necessary.
- Implementation choices: local single-user workspace; n8n is essential to processing; Python is only storage, retrieval and UI support.
- Isolation: new outputs/relaydesk repository; there is no existing branch or source to protect.
- Execution: tests first, inline staged implementation, one independent final code review. No remote push or public deployment requested.
- Stage 1: SQLite storage, actual LangChain BM25 retrieval, persistent API, atomic versioned approvals and durable outbox. Initial 11 tests passed after resolving the machine's inaccessible default pytest temporary directory by using a workspace-local cache.
- Stage 2: imported and published real n8n workflows. Ten synthetic cases and create/approve/handoff/resolve passed through actual webhooks. Upgraded the specialist stages to three native Tools Agent nodes with read-only procedure tools. A small-model nested output-format failure led to resolver JSON mode and explicit source-ID validation/formatting; classifier and reviewer retain native structured parsers.
- Stage 3: built the responsive portal, evidence/trace inspection, editable approval, procedure ingestion, export, optional browser speech, shared-key access and native startup scripts. Two Docker services built and passed health checks. The normal Windows launcher was exercised and initialized zero existing workflows, confirming that ordinary startup preserves canvas configuration.
- Independent review: fixed full-report retrieval bounds, category-filter ordering, consistent hazard response and steps, email batches/IDs/location, current-version summaries, outbox pagination/export, transition-based delivery counts, optional-email configuration preservation and access recovery. Every reported material defect received a regression check or actual browser verification.
- Ingress ruling: this pinned n8n release retains minimal trigger data even with detailed execution retention disabled. Moved limited secret redaction ahead of ingress and switched to signed 30-second JWTs. Rotated the prior service secret. Final database inspection found neither the active reusable service secret nor the original synthetic password in the retained trigger payload. Raw mail retention remains a documented optional-integration limit.
- Follow-up review: expanded labeled-secret redaction to punctuation/quoted values and metadata, preserving length. Added a persistent initialization marker so an interrupted core import resumes publication without resetting an intentionally unpublished existing workflow. Reproduced the failures first; 20 Python and 19 Node tests then passed. A simulated pending marker caused the default initializer to recover exactly one core workflow and publish it successfully.
- Browser verification: submitted a request, inspected evidence, edited/approved, observed a real n8n receipt and completed resolution on mobile. In-page access and resolution forms replace blocking native prompts. Literal angle brackets in a custom source rendered as text. Checked desktop/mobile bounds.
- Evaluation: final normal-support local model run used all three agents with no fallback flags; recorded in evaluation-results.json. All data used for verification was synthetic. Redundant self-generated test records were backed up under work/ and removed from the running demo; selected demonstrations and seeded fixtures remain.
